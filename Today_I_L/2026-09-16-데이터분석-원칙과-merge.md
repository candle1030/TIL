## 1. 질문을 코드보다 먼저 정한다

분석을 시작할 때는 "무슨 질문에 답할 건지"를 먼저 문장으로 적어야 한다.

이번 프로젝트의 질문 4가지: 카테고리별 금액, 월별 금액/주문 추이, 고객별 구매 금액, 주문 상태 분류.

## 2. 금액의 의미를 고정한다

- **completed 주문**: 상태가 "완료"인 주문만을 뜻한다.
- `line_total` = `quantity`(수량) × `unit_price`(단가)로 계산한 한 줄(품목)당 금액.
- `total_sales`라는 컬럼명이 있어도 이를 "진짜 회계상 매출"이라고 오해하면 안 된다. 할인, 배송비, 세금, 환불 같은 게 빠져 있을 수 있으므로 "완료 주문 기준 금액" 정도로 좁혀서 표현해야 한다.

## 3. 네 가지가 같은 기준을 써야 한다

분석 질문 = 코드의 계산 범위 = 저장된 csv/그래프 = 보고서 설명.

이 네 개가 서로 다른 기준을 쓰면(예: 코드는 전체 주문을 쓰는데 보고서는 "매출 증가"라고 씀) 프로젝트는 실행은 되지만 결과의 의미가 어긋난다.

## 4. 역할 구분: notebook / 스크립트 / 모듈

| 구분 | 역할 |
|---|---|
| notebook | 단계별로 눈으로 확인하며 학습·기록하는 곳 (셀을 여러 번 실행하면 예전 결과가 메모리에 남아있을 위험이 있음) |
| 실행 스크립트 | 프로젝트 전체를 처음부터 끝까지 다시 돌리는 파일 |
| 공통 모듈 | 검증·집계·시각화 로직을 재사용하도록 모아둔 코드 |

## 5. 원본(raw) 데이터에서 다시 시작한다

이미 가공된 processed 파일만 쓰지 않고, 매번 raw 데이터(customers, products, orders, order_items) 4종에서 전처리를 다시 실행한다. "어떤 규칙으로 바뀌었는지", "몇 행이 없어졌는지"를 나중에도 설명할 수 있어야 하기 때문이다. 원본은 절대 수정하지 않고, 변환 규칙은 코드로 남긴다.

## 6. 전처리 전후를 비교해서 증거로 남긴다

행 수, 열 수, 결측값, 중복값 등을 전처리 전/후로 비교한다. 단순히 "줄었다"가 아니라 "몇 행이, 왜 줄었는지"까지 설명할 수 있어야 한다.

## 7. PK 중복과 전체 행 중복은 다르다

- **PK(기본키)**: 각 표에서 한 행을 고유하게 식별하는 값 (예: `customer_id`, `order_id`)

```python
df.duplicated()          # 행 전체가 완전히 똑같은 중복 확인
df["id"].duplicated()    # 특정 키 값만 중복됐는지 확인
```

> `df["id"].duplicated()`가 더 중요하다. PK가 중복되면 나중에 병합할 때 행이 예상 밖으로 불어날 수 있다.

## 8. FK(외래키) 관계도 병합 전에 확인한다

- **FK(외래키)**: 다른 표의 PK를 참조하는 값 (예: `order_items`의 `product_id`는 `products`의 `product_id`를 가리킴)
- FK 값인데 부모 표에 실제로 없는 경우를 **미매칭**이라 하고, 이게 0인지 미리 확인하면 병합 사고를 막을 수 있다.

## 9. merge(병합)는 validate로 검증한다

- **merge**: 두 표를 공통 키로 합치는 작업.

```python
df.merge(
    other,
    on="key",
    how="left",
    validate="many_to_one",  # "왼쪽은 여러 행, 오른쪽은 고유해야 한다"는 관계를 강제로 확인
    indicator=True,           # 병합 결과에 _merge 컬럼 추가: both / left_only / right_only 확인 가능
)
```

> left merge(왼쪽 기준 병합)를 써도 오른쪽 키가 중복이면 행이 늘어날 수 있으므로, 병합 전후 행 수를 꼭 비교해야 한다.

## 10. union vs join

| 구분 | union | join |
|---|---|---|
| 의미 | 여러 조회 결과를 합침 | 여러 테이블을 연결 |
| 방향 | 행 방향 (위, 아래) | 열 방향 (옆) |
| 기준 | 컬럼 개수와 데이터 타입이 맞아야 함 | 보통 공통 키를 기준으로 연결 |
| 목적 | 같은 형태의 데이터를 하나로 합치기 | 서로 다른 정보를 연결하기 |

- union = 위아래로 쌓기
- join = 옆으로 연결하기
